The trusted bridge and `production_spawn` bind the workspace as `/scope`; they no longer bind the authoritative source repository. The model-visible Programmer `governed_exec` requires `inputs`; a whole-root `.` selection is denied at its dispatcher. Each selected directory is still bounded by the read grant and snapshot limits.

After payload completion and authoritative `CLOSED → populated 0 → QUIESCENT`, the controller rechecks the captured authoritative source bytes and observes changed, new, and deleted workspace files. It audits the observation before returning terminal ActionResult. Source drift or an unbounded output makes the scope INDETERMINATE rather than granting a success claim. The workspace may contain generated files and scratch mutations, but these are evidence only: no snapshot change is automatically promoted to authoritative state. An authorized Programmer source change is represented by a separate `governed_write` or `governed_patch` ActionRequest, authorized for its exact source target and audited before the next snapshot. This is the only current promotion mechanism. A future bulk promotion mechanism would need its own A2.3 authorization and conflict/provenance checks.
