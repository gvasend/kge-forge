The answer is **A: prospective result/output TYPE semantics**. It does not demand an executed Action, result artifact or observed value to admit a definition. No governing requirement was found that makes instantiated historical results mandatory in `result_contract`.

This narrows the earlier classification D: mandatory prospective information is not the same as an execution-evidence prerequisite. A full Action definition could be admitted before execution if its authoritative definition rules were complete. No partial type or relaxed O01 is necessary merely to separate declaration from occurrence. The actual unresolved issue is historical-definition normalization/expected-profile completeness, not the absence of executed outcomes.

A source declaration of possible PASS is not actual PASS. Likewise declared knowledge/output types do not create knowledge, root/slot transitions do not satisfy targets, and authority requirements do not grant authority.

These are meaningful prospective constraints. They do not, without an accepted normalization rule, determine a complete canonical finite result contract for every operation.
