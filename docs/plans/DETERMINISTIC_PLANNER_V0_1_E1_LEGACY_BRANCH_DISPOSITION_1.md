## Release-gate exception: explicit governing requirement exists

The user permits deferral to remove the legacy path as a release blocker **unless governing requirements explicitly require it**. They do: [Correction Plan 1 §8–9](DETERMINISTIC_PLANNER_V0_1_CORRECTION_PLAN_1.md) requires actual frozen-E1 operational import/validation and N-REAL in its conjunctive requalification gate. The migration-boundary decision also retains the restoration coverage floor until separately justified reconciliation.

Therefore this disposition defers the work but **does not waive its existing release obligation**. E2 is an additional canonical qualification path, not an automatic substitute for N-REAL. Before a future Planner v0.1 QUALIFIED claim, either N-REAL must pass or an explicit governing scope reconciliation must define a canonical-only release claim, replacement coverage and limitations. That reconciliation is not issued in this task. No historical plan is silently overwritten.

`LEGACY_RELEASE_GATE = RETAINED_PENDING_EXPLICIT_SCOPE_RECONCILIATION_OR_N_REAL_PASS`.

This preserves the strongest evidence-supported boundary: source-semantic reconstruction is deferred, the runtime is not blamed for unspecified legacy definitions, and qualification is not granted by changing the name of the test.
