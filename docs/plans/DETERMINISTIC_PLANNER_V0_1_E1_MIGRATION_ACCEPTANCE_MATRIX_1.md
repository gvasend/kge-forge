## Required negative-family coverage

The migration record must separately enumerate cases for unknown schema (MC01), ambiguity (MC01), malformed source (MC01), substitution and wrong pins (MC07), missing source (MC02/19), unexplained target fields (MC08), invalid identity conversion (MC06/07), provenance loss (MC08), cross-envelope joins (MC06), stale source (MC12/17/24), unsupported semantic value (MC03/11), and canonical admission failure (MC03–06/15–18). A test that only validates source syntax does not qualify its operational destination.

For every required source-dependent category, acceptance requires a positive admitted state, canonical persistence, fresh-process reload, source invalidation, admission rejection and dependent recomputation. Test both historical retention and current support withdrawal. Qualification fixtures must identify exactly which trust assertions are synthetic and must never become real E1 evidence.

For each result route, include wrong producer/type, stale/substituted report, wrong envelope, missing provenance, output outside the Action contract, historical proof used as current, and incompatible hold/history state. For actions, cover all63 concrete bindings in addition to shared semantic-value fixtures. For graph/proofs, cover the exact governed target rather than a generic synthetic name alone.

## Readiness and completion gates

M01 is ready to begin specification work now; implementation of M02–M07 is gated by its accepted contract/oracle outputs. A partially defined source family or typed rule is a blocker, not a registry wildcard. The implementation plan does not assert that currently missing semantics have been recovered.

A migration qualification record may state QUALIFIED_MIGRATION only when allMC01–MC26 pass at the same candidate identities, all required source dispositions and nested target fields are accounted for, all canonical admissions and required reentry profiles work, provenance is complete, cold determinism/invalidation pass, actual frozen semantics are independently derived, and preservation holds. No unexecuted required test can be marked PASS.

The synthetic reentry clone and actual frozen acceptance run are separate records: the former may acquire qualification-only evidence; the latter must retain all eight unresolved external boundaries and resume=false. A successful synthetic reentry cannot change the recorded frozen result.

The resulting17-element coverage crosswalk must be reviewed under the existing C06A/CE-02 predicates. Migration qualification alone does not authorize C06A-3, C07, E1 resume or Planner v0.1 QUALIFIED status. Preserve historical blocked attempts and perform the separately required correction-wide requalification and fresh adversarial review.

Planning validation only: no acceptance cases were executed in this task. Existing files and frozen E1 preservation were checked separately; the plan is not an implementation result.
