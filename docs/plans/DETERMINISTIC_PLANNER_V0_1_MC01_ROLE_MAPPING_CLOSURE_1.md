## Mapping functions and concrete scope

The contract companion defines `MAP_ROLE_B01` through `MAP_ROLE_B08` at the supported recorded-source boundary. Each enumerates source selectors, role discriminator, target-selector limitation, cardinality and rejection behavior. Where a native target selector is undefined, the function fails closed for operational use rather than returning a guessed role binding.

The common rule is exact pinned source identity + authorized semantic selector + target consumer + recorded scope/lineage/currentness. A locator alone is not a discriminator. There must be one authorized correspondence for each binding. There is no permissive precedence. Multiple roles require independently established claims/selectors; missing or conflicting required correspondence rejects. Raw content identity, declared artifact identity and each native Identifier domain remain separate.

Scope is the exact BR-C1 frozen context, not present-day applicability. Historical bytes can authenticate recorded frozen state; they cannot establish a different live envelope. Source EXECUTION and target REQUEST scopes are not equated. Every contract record includes source/target identity domains, affected Actions/fields, consumers, scope and lineage inherited from the authoritative signatures. Unknown reached consumer membership is explicitly retained as unresolved.
